SYSTEM CONTEXT: KDV Integrator - PDF Optimization Module1. System OverviewWe are adding a "Shift-Left" PDF optimization module to "KDV Integrator" (a Flask-based async middleware that syncs PDFs from Koha ILS to DSpace).Due to heavy CPU/RAM usage of Ghostscript, the optimization logic MUST be placed in an isolated Docker container (kdv-optimizer) that communicates with the main API (kdv-api) via HTTP and a shared volume.2. Architecture & Communicationkdv-api (Main App): Sync Flask app (1 worker, 4 threads). Runs background tasks.kdv-optimizer (New App): Mini Flask API. Internal network only.Shared Volume: /data/kdv_optimize/ mounted on both containers. Contains input/ and output/ folders.Contract: 1. kdv-api generates a UUID job_id.2. kdv-api copies original PDF to /data/kdv_optimize/input/{job_id}.pdf.3. kdv-api calls POST /optimize {"job_id": "..."}.4. kdv-api polls GET /optimize/{job_id} (timeout 130s) expecting {"status": "done|error|processing", "output_path": "...", "stats": {...}}.5. ONLY job_id is passed over HTTP. Path building happens safely inside each container.3. kdv-optimizer (The Engine)Execution: Must use concurrent.futures.ProcessPoolExecutor(max_workers=1) to prevent CPU starvation on the host. GIL must be bypassed.Engine: CLI Ghostscript via subprocess.run().OS Throttling: Subprocess MUST run with nice -n 15 and ionice -c 3.Timeout: Ghostscript process must have a strict 120s timeout (SIGKILL).Endpoints: POST /optimize, GET /optimize/<job_id>, GET /health, GET /ready.4. Business Logic & Heuristics (in kdv-api / services)Optimization is triggered ONLY if ALL conditions are met:Skip Flag: JSON payload skip_optimization is NOT true.Size/Page Rule (A or B):Rule A: Size > 50MB AND specific weight > 500KB/page.Rule B: Size > 100MB (unconditional, skip page counting).Page Counting: Use pdfinfo CLI (via subprocess with timeout). If pdfinfo fails/timeouts -> do NOT crash, fallback to True (force optimization).Disk Pre-flight: Shared volume free space must be > file_size * 2.5. If not, log skipped_no_disk and skip optimization.5. STRICT FALLBACK RULE (Crucial)If the optimization fails for ANY reason (Ghostscript timeout, larger output file, 0 bytes output, kdv-optimizer HTTP 503, any Exception):DO NOT fail the main archiving task.Silently fallback to uploading the original PDF to DSpace.Provide telemetry in task.result.6. Telemetry & CleanupCleanup: kdv-api MUST use a finally block to delete input/{job_id}.pdf and output/{job_id}.pdf regardless of success or exception.Telemetry fields required in task result:pdf_optimized: "true" | "false" | "skipped_by_user" | "skipped_by_size" | "skipped_no_disk"pdf_fallback_reason: "timeout" | "larger_output" | "empty_output" | "optimizer_unavailable" | "exception" | nullpdf_original_mb, pdf_final_mb, pdf_optimization_time_msGoalImplement the Python code for:kdv-optimizer/optimizer_app.py & services/pdf.py (The isolated service).src/services/pdf.py (The HTTP client logic in kdv-api).
